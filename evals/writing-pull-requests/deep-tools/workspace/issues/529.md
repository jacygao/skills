# Run the reviewer inside an operating-system sandbox

## Purpose

Run the reviewer at depth `deep` inside a sandbox the operating system enforces, so that nothing it or any process it starts can do reaches outside the round's own files, the network it needs, or the user's credentials.

## Why

The owner's decision on 2026-10-06: this is non-negotiable, and `deep` does not ship without it.

§ 4 Confinement holds a reviewer acting in good faith and no further. The refused calls are matched on command words, and `git "com"mit`, `env git commit` and `sh -c '…'` pass them. The tracked-file comparison detects after the fact and only inside the snapshot. Nothing today stops a shell at `deep` from:

- writing or deleting anywhere the user can: other repositories, the home directory;
- writing to the git directory the snapshot shares with the coding agent's worktree (`git branch -D`, deleting tags, rewriting refs);
- acting on GitHub with the user's own `gh` credentials: pushing, closing pull requests, deleting a repository;
- reading credential files and sending them anywhere over the network.

Claude Code's sandbox (Seatbelt on macOS, bubblewrap on Linux, published as `@anthropic-ai/sandbox-runtime`) and Codex CLI's (Seatbelt, and Landlock with seccomp) both enforce such a boundary at the operating-system level, on the command and every process it starts.

## Acceptance criteria

- [ ] At `deep`, the reviewer CLI and every process it starts run inside the sandbox, for `pi` and for Copilot, in a pane and detached.
- [ ] Writes are allowed only to the round's snapshot (excluding the shared git directory), its scratch directory and its session directory. A write anywhere else fails, including to the coding agent's worktree and to the git directory the snapshot shares.
- [ ] The network reaches only the reviewer's model API and the package registries the configured test command needs, by an allowlist. Anything else fails.
- [ ] Credential files are unreadable, and the reviewer's environment carries no GitHub token or `gh` credential. A `gh` or `git push` from inside fails.
- [ ] A test proves each boundary from inside a real sandboxed round: a write outside, a `.git` ref change, a request to a host not on the list, a read of a credential file, and `gh auth status`. Each fails, and the round reports it rather than crashing.
- [ ] Where the sandbox cannot be started (missing tool, unsupported platform), `deep` refuses to run, at setup, naming why. It never falls back to an unsandboxed shell.
- [ ] The harness specification's § 4 Confinement describes the sandbox as the first mechanism, ahead of the refusals and the comparison, which stay as a second layer. § 2 lists the sandbox as a dependency, and the setup check reports it.
- [ ] `npm run typecheck` and `npm test` pass.

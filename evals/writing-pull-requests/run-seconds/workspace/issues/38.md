# Write a timed-out suss.json when Harbor's agent timeout stops run

## Purpose

When Harbor's own agent timeout cancels `SussAgent.run`, suss still stops the harness, captures the patch and writes `suss.json`, with `status` `timed-out`.

## Acceptance criteria

- [ ] When Harbor cancels `run` (it wraps the agent phase in `asyncio.wait_for`), suss stops the harness inside the sandbox by the mechanism #35 settles, then captures the patch and writes `suss.json`
- [ ] That record has `status` `timed-out`, `run`'s exit code `null`, and `run_seconds` the time `run` had been going when it was stopped
- [ ] The cancellation still reaches Harbor after the record is written, so Harbor sees the trial as timed out
- [ ] § 3 of `docs/specs/suss-spec.md` says suss writes a `timed-out` record when Harbor's agent timeout stops the trial, as it does at `max_seconds`
- [ ] The `suss.json` example in § 3 shows `run_seconds` as a decimal, such as `1290.4`, as suss writes it
- [ ] A test cancels `run` through the stand-in environment and checks the record and the patch
- [ ] `uv run pytest` passes

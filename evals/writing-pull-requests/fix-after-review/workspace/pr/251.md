# Record that a marketplace install reaches the Bash tool's PATH and the hook

## Intent

Closes #54

- The note's first limit said whether a marketplace install puts the plugin's `bin/` on `PATH` was untested, and that nothing in it said an install and `--plugin-dir` were the same. M3 builds `squiz threads`, `squiz reply` and `squiz resolve`, which § 6 has the coding agent run by name, so an install that did not extend that `PATH` would leave those unusable.
- Both halves are now measured, and an install reaches the same two places as `--plugin-dir`.

## What changed

- **A `Reference` section for the install**: the two commands, the `marketplace.json` they want, `command -v squiz` resolving to the plugin's `bin/squiz` with the entry 16th, and the `hook_started` / `hook_response` pair showing `SubagentStop` running at `"exit_code": 0, "outcome": "success"`.
- **A `Decisions` entry**: the commands § 6 runs by name need nothing for an install.
- **The first two limits are replaced** by what was measured. Two narrower ones take their place: the marketplace source was a directory rather than a git host, and the install was declared at `local` scope.
- `settles` names § 9 alongside § 6, and `issue` names 54 alongside 39.

## What did not change

- **The registration.** `${CLAUDE_PLUGIN_ROOT}/bin/squiz hook` is what ran under the install, unchanged.
- **The hook's own `PATH`.** The note's headline finding is about the hook process, and an install does not change it. The plugin's `bin/` is on the Bash tool's `PATH`, not the hook's, which is why the registration names the root.

## Risks

- **Low: the install was from a local directory.** An install from a remote marketplace copies the plugin elsewhere, so the literal path would differ. What the note claims is that an install extends the Bash tool's `PATH` with the plugin's `bin/`, not which absolute path it adds. Recorded as a limit rather than left implied.

## Verification

```
npx tsc --noEmit
```

Clean. No source file changed.

The measurements were taken by installing at `local` scope, running one subagent in a session started afterwards with no `--plugin-dir`, and reading the stream with `--include-hook-events --output-format stream-json --verbose` plus `--debug-file`. The install, the marketplace and the `.claude/settings.local.json` it created were all removed afterwards, and `git status` was clean.

## Notes

- **A correction is recorded in the note rather than dropped.** An earlier attempt to observe the hook used `--debug` and a hook rewritten to leave a file behind, observed nothing, and read that as print mode running no `SubagentStop` hook at all. That was the wrong instrument: the note already documented `--include-hook-events` two sections above, and with it the firing was there. The note says so, so the same wrong turn is not taken again.
